# ADR-0005: Hand-written TypeScript API types

**Status:** Accepted · **Date:** 2026-09-18

## Context

The backend publishes an OpenAPI schema at `/openapi.json`. The frontend needs
TypeScript types for every request and response.

## Decision

Hand-write the contract in `frontend/src/types/api.ts`, mirroring the Pydantic
schemas. Revisit once the contract stabilises.

## Why

- **Readability in review.** The file is ~230 lines of plain interfaces a
  reviewer can read top to bottom. `openapi-typescript` output is machine-shaped
  — deeply nested `paths['/api/v1/projects']['get']['responses'][200]` lookups —
  and nobody reads it.
- **No generation step in the loop.** Generating requires the backend to be
  running, or a committed schema artefact plus a CI check that it is fresh.
  During a build phase where the contract changes several times an hour, that is
  friction with no payoff yet.
- **GeoJSON already has good types.** `Polygon`, `MultiPolygon` and
  `FeatureCollection` come from `@types/geojson`, so the geospatial half of the
  contract is already generated by someone else.
- **Drift is caught.** The integration tests assert the exact response shape on
  the backend, and the frontend tests use MSW handlers typed against
  `types/api.ts`. A field renamed on one side fails a test on the other.

## Rejected

**`openapi-typescript` in CI.** The correct answer for a large or long-lived
contract, and the documented upgrade path. Rejected now for the reasons above.

**`orval` or a similar client generator.** Generates hooks as well as types.
Would remove the hand-written `api/` modules, but its React Query integration is
opinionated and harder to adapt than the ~20 lines per feature it replaces.

## Cost

- The contract is stated twice, so a backend change can silently outpace the
  frontend types. Mitigated by tests on both sides, not eliminated.
- A new endpoint means editing two files.

## Upgrade path

When the API stabilises:

```bash
pnpm dlx openapi-typescript http://localhost:8000/openapi.json -o src/types/api.gen.ts
```

Then re-export the friendly aliases from `types/api.ts` so call sites do not
change.
